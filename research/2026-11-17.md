### 1. VS Code makin hari berasa makin berat di laptop kesayanganmu? _(Format: Feed — carousel evergreen, tersimpan di grid & gampang ditemukan lewat search/profil)_

**Angle:** Optimasi performa VS Code tanpa ganti laptop atau beralih editor dengan mematikan fitur rendering dan kalkulasi latar belakang yang boros CPU.

**Slide-by-slide:**
1. **VS Code Makin Lemot?** — Banyak dari kita yang sudah bertahun-tahun pakai VS Code dan merasa performanya kian melambat. Sebelum buru-buru ganti editor atau beli laptop baru, ada beberapa pengaturan bawaan yang bisa kita matikan untuk mengembalikan kecepatannya.
2. **1. Matikan Editor Minimap** — Minimap di pojok kanan pada dasarnya merender versi mini dari seluruh berkas secara terus-menerus saat kamu mengetik. Buka Settings dengan Ctrl + comma, cari Minimap, lalu hapus centang pada Editor: Minimap Enabled agar beban rendering GPU dan CPU berkurang.
3. **2. Nonaktifkan CodeLens** — Fitur CodeLens menghitung jumlah referensi dan runner tes di atas fungsi secara real-time setiap kali kamu scrolling. Hapus centang Editor: CodeLens di Settings. Kamu tetap bisa melihat referensi kapan saja pakai pintasan Shift + F12 tanpa membebani memori.
4. **3. Matikan Search On Type** — Pencarian otomatis saat mengetik memicu VS Code memindai seluruh direktori proyek pada tiap karakter. Buka Settings dan uncheck Search: Search On Type agar proses pencarian baru berjalan setelah kamu menekan tombol Enter.
5. **4. Audit Ekstensi Berat** — Buka panel Extensions dengan Ctrl + Shift + X lalu ketik @installed di kolom pencarian. Perhatikan nilai Activation Time dalam milidetik di tiap ekstensi. Hapus atau matikan plugin lama yang waktu muatnya tinggi namun jarang kamu gunakan.
6. **5. Sembunyikan node_modules** — Folder node_modules berisi ribuan berkas yang bisa bikin sidebar freeze jika tidak sengaja terklik. Tambahkan baris "**/node_modules": true pada bagian files.exclude di settings.json agar VS Code tidak perlu terus-menerus memindai folder tersebut.

### 4. Bikin efek animasi sekuensial saat scrolling tak perlu rumus matematika rumit! _(Format: Feed — carousel evergreen, tersimpan di grid & gampang ditemukan lewat search/profil)_

**Angle:** Pemanfaatan properti CSS native animation-range-start untuk mengatur penundaan animasi berbasis scroll secara bersih.

**Slide-by-slide:**
1. **Stagger Animation Tanpa Rumus** — Membuat elemen bermunculan berurutan saat di-scroll sering kali memicu kita menulis JavaScript rumit atau perhitungan math yang membingungkan. Padahal spesifikasi modern CSS sudah menyediakan solusinya secara bawaan.
2. **Masalah Pada animation-delay** — Properti animation-delay konvensional dirancang untuk timeline berbasis waktu detik atau milidetik. Saat kita beralih ke scroll-driven animation, penundaan waktu tersebut tidak lagi efektif untuk mengatur posisi elemen.
3. **Solusi: animation-range-start** — CSS memperkenalkan animation-range-start khusus untuk scroll timeline. Properti ini memungkinkan kita menentukan titik awal berjalannya animasi relatif terhadap persentase progres scroll layar pengguna.
4. **Gunakan Fungsi sibling-index()** — Kita bisa memanfaatkan sibling-index() untuk menghitung penambahan range secara dinamis. Misalnya dengan menambahkan offset 2.5% per elemen bersaudara, efek kemunculan bertahap akan tercipta secara presisi.
5. **Hasil Kode Lebih Bersih** — Tanpa perlu framework JavaScript tambahan atau logika kustom yang rawan bug, animasi scroll sekuensial bisa diselesaikan hanya dalam beberapa baris CSS deklaratif yang sangat ringan.
6. **Cobalah di Proyek Modernmu** — Fitur scroll-driven animation ini sudah didukung di browser modern berbasis Chromium. Yuk mulai sederhanakan stylesheet proyekmu dan hilangkan kompleksitas koding yang tidak perlu!

[Sumber](https://css-tricks.com/staggering-scroll-driven-animations-with-animation-range-start/)
