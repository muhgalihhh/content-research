### 1. Nggak sadar API Go kamu bikin bug silently cuma gara-gara struct key beda kapitalisasi? _(Format: Feed — carousel evergreen, tersimpan di grid & gampang ditemukan lewat search/profil)_

**Angle:** Membahas pembaharuan ketat di paket encoding/json/v2 Go 1.27 yang menyelesaikan penanganan case-insensitive dan nil slice.

**Slide-by-slide:**
1. **Masalah Mengintai di Go v1** — Di Go v1, JSON parser sangat forgiving. Kalau frontend ngirim key kapital seperti "ADMIN", v1 tetap memetakan ke field struct Admin tanpa protes. Ini sering memicu celah keamanan kalau ada gateway yang cuma ngecek lower-case "admin".
2. **Go 1.27 Rilis encoding/json/v2** — Di versi terbaru Go 1.27, rilis stabil encoding/json/v2 membawa aturan yang lebih ketat secara default. Parser v2 tidak lagi mencocokkan key secara case-insensitive untuk menghindari disagreement antar parser.
3. **Nil Slice Sekarang Menjadi []** — Masalah klasik frontend crash karena .map() pada respon null kini selesai. Di v2, nil slice di-marshal menjadi [] secara default, bukan null, kecuali kamu secara eksplisit menyalakan opsi FormatNilMapAsNull.
4. **Penanganan Custom Type Lebih Fleksibel** — Kamu tidak perlu lagi membuat wrapper type baru untuk tipe bawaan seperti time.Duration. Lewat interface UnmarshalFromFunc di v2, kamu bisa mendaftarkan fungsi decode khusus langsung di tingkat pemanggilan.
5. **Performa Unmarshal Hingga 10x Lebih Cepat** — Dengan arsitektur baru yang memisahkan jsontext (syntax) dan v2 (semantics), benchmark internal Go menunjukkan proses Unmarshal bisa lebih cepat hingga 10x lipat berkat interface UnmarshalJSONFrom.

### 2. Tahu gak request input casting di Laravel bisa bikin aplikasi kecolongan nilai invalid? _(Format: Feed — carousel evergreen, tersimpan di grid & gampang ditemukan lewat search/profil)_

**Angle:** Mengulas fitur parameter strict pada helper input Laravel 13.40 yang mencegah bug tersembunyi akibat php type casting bawaan.

**Slide-by-slide:**
1. **Bahaya Casting Bawaan Laravel** — Mengambil parameter query seperti $request->integer('per_page') sangat praktis. Tapi kalau user jahat ngirim string 'abc123', PHP casting mengunduh nilainya jadi 0 tanpa memberikan error atau default value yang diharapkan.
2. **Fitur Baru: Strict Request Input** — Laravel 13.40 menambahkan parameter strict: true pada helper request input. Jika input tidak valid sesuai tipe data yang diminta, Laravel langsung mengembalikan nilai default kamu.
3. **Validasi Ketat untuk Integer & Float** — Dengan opsi strict: true, angka desimal atau teks yang dikirim ke $request->integer() tidak akan dipaksa di-cast, melainkan dianggap invalid sehingga aman dari bug tak terduga.
4. **Penanganan Boolean Yang Lebih Aman** — Tanpa opsi strict, nilai string seperti 'maybe' pada boolean helper bisa bernilai false. Menggunakan strict: true memastikan hanya nilai boolean valid (seperti true, false, 1, 0) yang diproses.
5. **Kapan Harus Dipakai?** — Gunakan strict: true untuk opsional query parameter seperti pagination page size atau pencarian. Untuk form input utama yang wajib, tetap gunakan Form Request Validation.
