### 3. Go app kamu makan CPU banyak padahal nggak ada memory leak? Ini dia solusinya! _(Format: Feed — carousel evergreen, tersimpan di grid & gampang ditemukan lewat search/profil)_

**Angle:** Menjelaskan fenomena CPU usage tinggi di Go karena Garbage Collection yang over-eager, dan solusi praktis untuk mengatasinya dengan mengatur memory limit, yang sangat berguna bagi developer Go.

**Slide-by-slide:**
1. **Optimasi Go App: CPU Tinggi Bukan Berarti Memory Leak!** — Pernah ngalamin aplikasi Go kamu memakan banyak CPU padahal gak ada indikasi memory leak? Ternyata, biang keroknya bisa jadi si Garbage Collector (GC)! Mari kita kupas tuntas.
2. **Fenomena Aneh: CPU Spike, Memory Aman?** — Kasus unik di mana servis Go mengalami peningkatan penggunaan CPU drastis, antara 25-60%, tapi monitoring memory terlihat stabil. Bahkan, kadang bisa OOM-killed tanpa alasan jelas!
3. **Pelaku Utama: Go's Garbage Collector (GC)** — Ternyata, penyebabnya bukan memory leak, melainkan GC Go yang bekerja terlalu agresif. Saat memory tidak dibatasi, GC akan sering berjalan mencoba mengklaim kembali memori, menghabiskan CPU.
4. **Kenapa GC Bisa Boros CPU?** — Tanpa batas memori yang jelas, Go runtime cenderung merasa memiliki 'memori tak terbatas'. GC akan terus-menerus mencoba mengosongkan memori yang tidak terpakai, menyebabkan siklus GC yang sering dan memakan CPU.
5. **Solusi Praktis: Atur GOMEMLIMIT** — Untuk mengatasi ini, gunakan variabel lingkungan GOMEMLIMIT. Ini memberitahu Go berapa batas memori yang harus digunakan, sehingga GC akan bekerja lebih efisien dan tidak over-eager.
6. **Implementasi & Hasilnya** — Misalnya, set GOMEMLIMIT='750MB' untuk aplikasi yang berjalan di kontainer 1GB. Dengan batas ini, GC akan mulai bekerja saat penggunaan memori mendekati 750MB, mengurangi frekuensi kerja dan CPU usage.
7. **Takeaway Penting untuk Dev Go** — Penting untuk memahami cara kerja GC Go. Jangan langsung berasumsi memory leak saat CPU tinggi. Pertimbangkan GOMEMLIMIT sebagai langkah awal optimasi untuk aplikasi Go Anda.

1. **Rahasia Desain Rapi: Naming Convention di UI/UX** — Berapa kali Anda bingung mencari layer 'Rectangle 1 copy 3' di Figma? Naming convention yang konsisten adalah kunci untuk desain yang terorganisir, mudah dikelola, dan kolaboratif. Yuk, kita pelajari!
2. **Kenapa Naming Itu Penting?** — Naming bukan cuma soal kode, tapi juga fondasi desain yang baik. Nama yang jelas dan terstruktur memudahkan desainer lain (atau Anda di masa depan) memahami komponen dan flow desain tanpa kesulitan.

### 2. Lupakan Media Queries lama! Saatnya kenalan dengan Container Queries untuk responsive design yang lebih cerdas. _(Format: Feed — carousel evergreen, tersimpan di grid & gampang ditemukan lewat search/profil)_

**Angle:** Menjelaskan perbedaan fundamental antara Media Queries dan Container Queries, serta bagaimana Container Queries memberdayakan desainer dan developer untuk membuat komponen yang benar-benar responsif dan modular.

**Slide-by-slide:**
1. **Container Queries: Revolusi Responsive Design yang Wajib Kamu Tahu!** — Media Queries sudah jadi standar responsive design, tapi ada fitur CSS baru yang lebih powerful: Container Queries! Ini akan mengubah cara kita membangun komponen UI yang fleksibel.
2. **Media Queries: Baik, Tapi Ada Batasnya** — Media Queries merespons ukuran viewport secara keseluruhan. Ini bagus untuk tata letak halaman, tapi kurang fleksibel untuk komponen individual yang harus beradaptasi di berbagai konteks.
3. **Masalah Responsive Lama: Konteks Global** — Komponen yang sama bisa muncul di sidebar sempit atau area konten utama lebar. Dengan Media Queries, sulit membuat komponen itu beradaptasi 'secara internal' tanpa duplikasi kode atau hack.
4. **Selamat Datang Container Queries!** — Container Queries memungkinkan sebuah komponen merespons ukuran kontainer induknya, bukan lagi ukuran viewport global. Ini berarti komponen bisa 'pintar' dan menyesuaikan diri di mana pun ia diletakkan.
5. **Kenapa Ini Game Changer untuk UI/UX?** — Desainer kini bisa membuat komponen yang benar-benar modular dan reusable. Setiap komponen punya 'otaknya sendiri' untuk beradaptasi, tanpa peduli layout halaman secara keseluruhan. Lebih fleksibel dan efisien!
6. **Contoh Penggunaan Praktis** — Bayangkan sebuah kartu produk. Dengan Container Queries, kartu ini bisa mengubah layoutnya (misal: gambar di atas teks atau di samping teks) tergantung pada lebar kolom di mana ia berada. Keren, kan?
7. **Desainer & Developer, Saatnya Adaptasi!** — Container Queries sudah didukung browser utama. Ini adalah skill baru yang akan meningkatkan kualitas dan fleksibilitas desain serta pengembangan Anda. Jangan sampai ketinggalan!
