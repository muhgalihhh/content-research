1. **Status KMP di 2026** — Kekhawatiran bahwa KMP hanya eksperimen kini sudah terjawab. ### 2. Masih memaksakan satu prompt raksasa untuk memproses data rumit sampai AI kamu sering halusinasi format? _(Format: Feed — carousel evergreen, tersimpan di grid & gampang ditemukan lewat search/profil)_

**Angle:** Memperkenalkan pola prompt chaining dengan Spring AI sebagai solusi arsitektur deterministik yang memecah proses rumit menjadi alur sekuensial yang mudah diaudit.

**Slide-by-slide:**
1. **Jebakan One Big Prompt** — Kita sering tergoda menulis satu prompt panjang: meminta AI mengekstrak data, menormalkan satuan, mengurutkan nilai, lalu membuat tabel sekaligus. Sayangnya, hasilnya sering meleset sedikit pada unit atau urutan. Memperbaiki prompt raksasa tersebut justru menghabiskan waktu lebih banyak daripada menyelesaikan inti masalahnya.
2. **Solusi: Pola Prompt Chaining** — Daripada satu prompt serba bisa, pecah tugas menjadi rantai prompt kecil berurutan. Output langkah pertama menjadi input langkah kedua, di mana masing-masing langkah hanya memegang satu tanggung jawab spesifik. Pola ini membuat alur data terprediksi dan mudah diuji secara modular.
3. **Implementasi 4 Tahap Berantai** — Contohnya pada Spring AI, pengolahan laporan teks dipecah menjadi 4 langkah: Step 1 mengekstrak angka metrik, Step 2 menormalkan format satuan yang bercampur, Step 3 mengurutkan angka secara numerik, dan Step 4 memformatnya menjadi tabel markdown rapi. Tiap langkah memiliki kontrak output yang jelas.
4. **Pentingnya Validation Gate** — Dalam produksi nyata, jangan biarkan teks mengalir mentah antar-langkah tanpa pengecekan. Pasang gate sederhana, misalnya regex deterministik, untuk memvalidasi apakah output langkah sebelumnya sudah sesuai kontrak format. Jika gagal, sistem bisa langsung melakukan retry terarah sebelum berlanjut ke tahap berikutnya.
5. **Kesiapan untuk Sistem Produksi** — Pola chaining membutuhkan 4 kali pemanggilan model, sehingga kamu wajib menambahkan timeout kolektif dan retry policy dengan exponential backoff untuk menangani rate limit. Terapkan juga structured logging yang mencatat durasi serta ukuran respons tiap tahap tanpa membocorkan data sensitif pengguna.

**Angle:** Membahas teknik sanitasi data bolak-balik (reversible anonymization) di Laravel menggunakan package Laranon agar interaksi dengan AI tetap aman dari pelanggaran privasi.

**Slide-by-slide:**
1. **Tantangan Privasi Data pada AI** — Mengirim teks langsung dari aplikasi ke API LLM pihak ketiga berisiko melanggar kepatuhan data privasi jika teks memuat nama, nomor identitas, atau detail rekening bank. Mengaburkan data secara permanen sering kali membuat jawaban dari AI tidak bisa langsung diproses kembali oleh sistem.
2. **Mengenal Solusi Laranon** — Package Laranon karya Eduardo Lázaro hadir untuk ekosistem Laravel 12 dan PHP 8.2+. Fungsinya mengganti data sensitif (PII) menjadi token placeholder sebelum teks dikirim ke model LLM, lalu memetakan kembali nilai aslinya saat jawaban diterima oleh aplikasi.
3. **Mekanisme Kerja Dua Arah** — Panggil method anonymize() untuk mengubah teks asli menjadi teks ber-token beserta token map yang tersimpan aman di server lokal. Kirim teks bertopeng tersebut ke LLM, dan begitu respon diterima, jalankan restore() untuk mengembalikan token kembali menjadi data asli seperti nama pengguna.
4. **Session dan Scope Management** — Untuk percakapan multiturn, Laranon menyediakan fitur Anonymizer session di memori yang mengikat token serupa di setiap riwayat obrolan. Untuk asynchronous job, gunakan fitur scope yang mengenkripsi peta token ke dalam cache atau database menggunakan application key Laravel milikmu.
5. **Deteksi Cerdas Kontekstual** — Laranon tidak sekadar mencari kata acak, melainkan menggunakan kamus nama, gelar kehormatan, dan konteks kata di sekitarnya guna membedakan nama umum dengan kata biasa. Package ini juga menyediakan fitur logging tap dan HTTP macro Http::scrubPii() untuk mencegah kebocoran data di file log produksi.
