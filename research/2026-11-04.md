**Slide-by-slide:**
1. **Solusi Real-Time Tanpa Polling** — Inertia.js v3.11 dan inertia-laravel v3.7.0 resmi membawa fitur Live Props. Fitur ini bikin prop di halaman otomatis reload saat event broadcast tiba tanpa perlu teknik polling manual.
2. **Cara Setup di Sisi Server** — Di bagian backend Laravel, kamu cukup membungkus prop dengan Inertia::live() lalu teruskan event yang memicu refresh. Inertia otomatis membaca channel dari method broadcastOn() pada event tersebut.
3. **Konfigurasi di Sisi Klien** — Pada klien, cukup sediakan transport ke createInertiaApp() menggunakan helper echo() dari setup configureEcho(). Paket tambahan untuk Vue, React, atau Svelte sifatnya opsional jika tidak pakai fitur ini.

5. **Pengaturan Throttle & Tab** — Secara default, live reloads dibatasi satu kali per prop tiap detiknya. Kamu juga bisa mengatur agar proses reload menunggu tab aktif kembali lewat konfigurasi bawaan.

**Angle:** Mengedukasi developer PHP mengenai fitur keamanan terbaru di Composer 2.11 yang menahan instalasi versi paket baru untuk menghindari kode berbahaya.

**Slide-by-slide:**
1. **Lapisan Keamanan Baru Composer** — Composer 2.11.0 resmi memperkenalkan cooldown dependency policy. Fitur ini memungkinkan kamu mengatur waktu tunggu agar Composer melewati versi paket yang baru saja dipublikasikan.
2. **Bagaimana Cara Kerjanya?** — Jika ada versi berbahaya yang diunggah ke package, sistem cooldown mencegah instalasinya selama durasi waktu yang kamu tentukan. Jika versi itu telanjur dilaporkan dan dihapus, project kamu aman.
3. **Cara Mengaktifkan Kebijakannya** — Kebijakan ini mati secara default sampai kamu menetapkan durasi waktu pada bagian config.policy di composer.json, seperti string '1 day' atau '6 hours'.
4. **Pengecualian dan Kedaruratan** — Perintah composer install tetap berjalan normal tanpa terpengaruh cooldown. Jika butuh perbaikan keamanan darurat secara instan, cukup tambahkan flag --no-cooldown saat menjalankan update.
