### 1. Seberapa besar sih 'dosa' Git commit kamu? _(Format: Feed — carousel evergreen, tersimpan di grid & gampang ditemukan lewat search/profil)_

**Angle:** Membahas ukuran commit Git dan dampaknya pada performa repository, serta tips untuk mengoptimalkannya. Ini adalah pengetahuan praktis yang sering diabaikan developer.

**Slide-by-slide:**
1. **Seberapa Besar Commit Git Kamu?** — Commit Git adalah inti dari kontrol versi. Tapi tahukah kamu, ukuran commit bisa memengaruhi performa repositorymu? Yuk, kita bedah lebih lanjut!
2. **Apa Itu Git Commit?** — Git commit adalah 'snapshot' dari perubahan-perubahan pada proyekmu. Setiap commit menyimpan riwayat modifikasi kode, bukan hanya sekadar menambah file baru.
3. **Anatomi Sebuah Commit** — Sebuah commit terdiri dari metadata (author, timestamp, pesan commit) dan pointer ke perubahan file. Ukuran file yang diubah atau ditambahkan sangat memengaruhi total ukuran commit.
4. **Dampak Ukuran Commit** — Commit yang terlalu besar bisa memperlambat operasi Git seperti clone, fetch, atau push. Ini juga bisa membuat proses review kode jadi lebih sulit dan memakan waktu.
5. **Tips Mengurangi Ukuran Commit** — Manfaatkan .gitignore untuk mengabaikan file yang tidak perlu. Gunakan git gc secara berkala, atau pertimbangkan git filter-repo untuk menghapus riwayat file besar yang sudah tidak relevan.
6. **Best Practices** — Biasakan atomic commit: satu commit untuk satu perubahan logis. Hindari commit file biner besar. Jika terpaksa, gunakan Git LFS untuk mengelola aset berukuran besar secara terpisah.
7. **Jaga Commit Tetap 'Bersih'!** — Commit yang bersih dan ringkas bukan hanya masalah performa, tapi juga keterbacaan dan kolaborasi. Mari bersama membangun repository yang sehat!

**Angle:** Memberikan tips konkret tentang penamaan komponen UI, variabel, atau layer di tool desain untuk menjaga konsistensi dan kolaborasi dalam tim.

**Slide-by-slide:**
1. **Seni Penamaan dalam Desain UI/UX** — Penamaan dalam desain bukan cuma soal label, tapi kunci konsistensi dan kolaborasi. Sering bingung menamai komponen? Tenang, kamu tidak sendiri!
2. **Kenapa Naming Penting?** — Penamaan yang baik mempercepat alur kerja, memudahkan handoff ke developer, dan menjaga skalabilitas proyek. Bayangkan kalau semua layer namanya 'Group 1', 'Group 2'!
3. **Prinsip Dasar Penamaan** — Jelas, konsisten, dan prediktif. Nama harus langsung menggambarkan fungsi atau isi dari komponen. Hindari singkatan yang ambigu atau terlalu umum.

5. **Struktur Penamaan Efektif** — Contoh: [Komponen]/[Status]/[Ukuran]. Misalnya, 'Button/Primary/Large' atau 'Input/Default/Text'. Ini membuat komponen mudah dicari dan dipahami.
6. **Tips Praktis Tambahan** — Gunakan bahasa yang konsisten (misal: Bahasa Inggris), hindari karakter spesial, dan manfaatkan fitur auto-rename di tool desainmu. Lakukan audit penamaan secara berkala.
7. **Desain Lebih Rapi & Mudah Dikelola** — Dengan sistem penamaan yang baik, file desainmu akan lebih terorganisir. Tim developer juga pasti lebih senang karena mudah mengidentifikasi elemen. Yuk, mulai terapkan!

### 3. Berhenti perlakukan Container Queries seperti Media Queries! _(Format: Feed — carousel evergreen, tersimpan di grid & gampang ditemukan lewat search/profil)_

**Angle:** Menjelaskan perbedaan mendasar antara CSS Container Queries dan Media Queries, serta kapan dan mengapa harus menggunakan masing-masing untuk desain responsif modern.

**Slide-by-slide:**
1. **Container Queries ≠ Media Queries!** — CSS Container Queries itu game-changer, tapi banyak yang salah kaprah dan menyamakannya dengan Media Queries. Padahal, ada perbedaan fundamental yang harus kamu tahu!
2. **Apa Itu Media Queries?** — Media Queries responsif terhadap ukuran viewport keseluruhan browser. 'Jika lebar layar > 768px, maka…'. Ini bagus untuk layout global halaman.
3. **Apa Itu Container Queries?** — Container Queries memungkinkan komponen merespons ukuran 'parent container'-nya, bukan ukuran viewport. 'Jika lebar card ini > 300px, maka…'.
4. **Kenapa Ini Penting?** — Dengan Container Queries, komponen UI jadi lebih mandiri dan 'composable'. Satu komponen bisa punya tampilan responsif berbeda tergantung di mana ia diletakkan, tanpa perlu media queries spesifik di setiap tempat.
5. **Kapan Pakai Media Queries?** — Gunakan Media Queries untuk layout besar atau perubahan tata letak yang berlaku di seluruh halaman (misal: sidebar jadi di bawah di mobile).
6. **Kapan Pakai Container Queries?** — Pilih Container Queries untuk membuat komponen yang benar-benar responsif secara internal. Contoh: card produk yang tampilannya berubah saat ditempatkan di sidebar sempit atau area konten lebar.
7. **Membangun UI yang Lebih Fleksibel** — Memahami perbedaan ini akan membantumu membangun sistem desain dan UI yang jauh lebih fleksibel, modular, dan mudah dikelola. Yuk, optimalkan desain responsifmu!

[Sumber](https://smashingmagazine.com/2026/09/stop-treating-css-container-queries-traditional-media-queries/)
