### 4. Aplikasi PHP kamu sering crash mendadak akibat 'Allowed memory size exhausted' saat pakai Queue Worker atau Octane? _(Format: Feed — carousel evergreen, tersimpan di grid & gampang ditemukan lewat search/profil)_

**Angle:** Mengidentifikasi empat penyebab utama terjadinya memory leak pada proses PHP bertipe long-lived serta solusi praktis untuk mengatasinya.

**Slide-by-slide:**
1. **Membongkar Rahasia Memory Leak di PHP** — Pada request PHP-FPM biasa, memori akan otomatis dibebaskan begitu request selesai. Namun pada proses long-lived seperti daemon, queue worker, dan Laravel Octane, kebocoran memori kecil akan terus menumpuk hingga membuat proses mati.
2. **Penyebab 1: Menyimpan Cache Tanpa Batas** — Menyimpan data pada properti statis atau array global tanpa membersihkannya adalah penyebab paling umum. Solusinya, gunakan WeakMap agar data otomatis terhapus saat objek utamanya dibebaskan dari memori.
3. **Penyebab 2: Circular References & Garbage Collector** — Dua objek yang saling merujuk tidak bisa langsung dibebaskan begitu saja. Panggil fungsi gc_collect_cycles() secara berkala pada pemrosesan data berukuran besar agar garbage collector bisa membersihkan siklus tersebut.
4. **Penyebab 3: Mendaftarkan Event Listener di Dalam Loop** — Mendaftarkan event listener atau observer di dalam job handler atau controller akan menambah listener baru di setiap eksekusi. Daftarkan event listener hanya sekali pada boot() Service Provider aplikasi kamu.
5. **Penyebab 4: Fitur Query Log Lupa Dimatikan** — Fitur query log Laravel akan menyimpan semua riwayat query ke dalam memori. Pastikan fitur ini tidak aktif pada lingkungan produksi atau pastikan kamu rutin memanggil DB::flushQueryLog().
6. **Gunakan php-meminfo untuk Melacak Leak** — Jika kebocoran sulit ditemukan, gunakan ekstensi php-meminfo untuk membuat dump objek di memori. Hitung class mana yang memiliki jumlah instance tidak wajar untuk menemukan akar masalahnya.
