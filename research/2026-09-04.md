### 2. Capek ngetik panjang buat SSH ke server yang beda-beda? _(Format: Feed — carousel evergreen, tersimpan di grid & gampang ditemukan lewat search/profil)_

**Angle:** Tips praktis yang sangat berguna untuk developer yang sering berinteraksi dengan banyak server, meningkatkan efisiensi kerja sehari-hari.

**Slide-by-slide:**
1. **Bye-bye SSH Command Panjang!** — Sering SSH ke banyak server dengan user, port, dan private key yang beda-beda? Ngetik command panjang tiap kali bisa buang waktu dan rawan typo lho! Ada cara yang lebih cerdas nih.
2. **Kenalan Sama ~/.ssh/config** — File ~/.ssh/config adalah jagoan rahasia para developer untuk manajemen koneksi SSH. Di sini kamu bisa definisikan shortcut dan pengaturan khusus untuk tiap server.
3. **Cara Kerjanya?** — Kamu cukup membuat entri untuk setiap host di file config. Lalu, tinggal panggil dengan nama alias yang kamu buat. Semua detail seperti user, host, port, dan path key akan otomatis terisi.
4. **Contoh Konfigurasi Simpel** — Host my-dev-server HostName 192.168.1.100 User devuser Port 2222 IdentityFile ~/.ssh/id_rsa_dev. Dengan ini, kamu cukup ketik ssh my-dev-server di terminal. Praktis, kan?
5. **Lebih dari Sekadar Shortcut** — Selain shortcut, kamu bisa atur parameter lain seperti ForwardAgent, ControlMaster, atau ProxyCommand untuk koneksi yang lebih canggih dan aman. Produktivitasmu auto-naik!
6. **Mulai Sekarang, Bikin SSH-mu Lebih Smart!** — Dengan ~/.ssh/config, kamu nggak cuma hemat waktu, tapi juga mengurangi potensi error. Pekerjaanmu jadi lebih terstruktur dan efisien. Jangan tunda lagi, yuk implementasikan!
7. **Tips Lain? Follow xharp.dev!** — Mau tips dan trik pengembangan software lainnya yang bikin kerjaanmu makin produktif? Jangan lupa follow xharp.dev! Kami berbagi insight terbaik untuk developer dan desainer.

### 3. Dokumentasi Markdown-mu gitu-gitu aja? Yuk, bikin lebih rapi dan powerful! _(Format: Feed — carousel evergreen, tersimpan di grid & gampang ditemukan lewat search/profil)_

**Angle:** Meningkatkan kualitas dokumentasi adalah skill penting bagi developer. Konten ini memberikan trik Markdown yang mungkin belum banyak diketahui.

**Slide-by-slide:**
1. **Markdown Lebih dari Sekadar Heading!** — Kamu pasti udah sering pakai Markdown buat README atau dokumentasi project. Tapi tahu nggak, ada trik-trik simpel yang bisa bikin dokumenmu jauh lebih bersih, rapi, dan gampang dibaca?
2. **Definisi List untuk Istilah Penting** — Jangan cuma pakai bullet point! Untuk daftar istilah atau opsi, Definition List lebih pas. Cukup pakai Term : Description. Dokumen teknismu jadi lebih terstruktur dan profesional.
3. **Blockquote untuk Kutipan Kode atau Referensi** — Selain pakai backtick untuk kode inline, gunakan blockquote (>) untuk menyorot kutipan panjang atau referensi penting. Ini membantu pembaca membedakan informasi utama dengan konteks tambahan.
4. **Collapse Details (HTML di dalam Markdown)** — Punya bagian yang panjang tapi nggak selalu relevan? Pakai <details> dan <summary> dari HTML! Ini bisa bikin dokumenmu ringkas, tapi informasi tetap lengkap dan bisa dibuka kalau dibutuhkan.
5. **Task Lists untuk Checklist Proyek** — Fitur Task Lists (- [ ] Item) ini super berguna untuk melacak progres atau daftar tugas. Bikin README-mu jadi interaktif dan fungsional, apalagi buat kolaborasi tim.
6. **Tingkatkan Kualitas Dokumentasimu!** — Dengan trik-trik ini, dokumentasi Markdown-mu nggak cuma informatif, tapi juga user-friendly. Pembaca akan lebih mudah memahami dan menemukan informasi yang mereka cari.
