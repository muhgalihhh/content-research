**Angle:** Konten ini memberikan tips praktis penggunaan Markdown yang sering terlewat tapi bisa sangat meningkatkan readability dan maintainability dokumentasi teknis, relevan untuk developer.

**Slide-by-slide:**
1. **Markdown Lebih dari Sekadar Bold!** — Sebagai developer, kita sering pakai Markdown untuk README, dokumentasi API, atau catatan proyek. Tapi, yakin udah pakai fitur tersembunyi Markdown secara maksimal? Yuk, bikin dokumen teknis kamu makin rapi dan mudah dibaca!

### 3. Repository Git kamu sering kotor sama file-file yang gak penting? 😥 Ini solusinya! _(Format: Feed — carousel evergreen, tersimpan di grid & gampang ditemukan lewat search/profil)_

**Angle:** Memberikan trik praktis untuk mengelola file yang diabaikan di Git secara default, membantu menjaga kebersihan repository dan fokus pada kode yang relevan.

**Slide-by-slide:**
1. **Repo Git Rapi = Hati Senang! ❤️** — Sebagai developer, seringkali kita berhadapan dengan repository Git yang 'kotor' karena banyak file sementara atau generated files ikut terdeteksi. Ini bisa mengganggu fokusmu ke kode utama.
2. **Masalah .gitignore Konvensional** — Biasanya kita pakai `.gitignore` untuk exclude file/folder. Tapi, daftarnya bisa sangat panjang dan terkadang ada yang terlewat. Hasilnya? File-file yang seharusnya diabaikan malah muncul di Git status.
3. **Strategi: 'Ignore Everything by Default'** — Gimana kalau kita balik logikanya? Daripada exclude satu per satu, kita bisa 'ignore everything by default' lalu secara eksplisit 'include' file yang memang kita inginkan masuk ke repo Git.
4. **Cara Implementasi Praktis** — Di file `.gitignore` kamu, tambahkan baris `*` (untuk ignore semua file/folder) lalu tambahkan `!` diikuti nama file/folder yang ingin kamu sertakan. Contoh: `*`, `!index.html`, `!src/`, `!public/`.
5. **Contoh Penggunaan di Proyek** — Untuk proyek frontend sederhana, `.gitignore` kamu mungkin terlihat seperti ini: `*`, `!README.md`, `!package.json`, `!package-lock.json`, `!public/`, `!src/`. Ini menjaga agar hanya file sumber dan konfigurasi penting yang masuk Git.
6. **Manfaat untuk Kebersihan Repo** — Strategi ini memaksa kamu untuk lebih sadar akan apa yang sebenarnya perlu dilacak oleh Git. Hasilnya? Repo yang jauh lebih bersih, ukuran yang lebih kecil, dan commit yang lebih bermakna. Tidak ada lagi folder `node_modules` yang tidak sengaja ter-commit!
7. **Mulai Terapkan Sekarang!** — Coba terapkan "ignore everything by default" di proyek barumu atau refactor `.gitignore` proyek lama. Ini adalah kebiasaan baik yang akan membuat hidup developer lebih tenang. Selamat mencoba!
